# TDSD Testnet Deployment

This checklist turns the TDSD contract workspace into a real TON testnet asset
connected to the Tuda Suda backend.

## Prerequisites

- Node.js 20+.
- TON testnet wallet funded with test TON.
- Public HTTPS metadata URL serving `metadata/tdsd-metadata.json`.
- Backend production/testnet env prepared.
- No private keys or seed phrases stored in the repository.

## 1. Install Contract Dependencies

```bash
cd tuda-suda/contracts
npm install
cp .env.contracts.example .env.contracts
```

Edit `.env.contracts`:

```env
TON_NETWORK=testnet
TDSD_METADATA_URL=https://app.tudasuda.tech/tdsd-metadata.json
TDSD_OWNER_ADDRESS=<admin wallet address>
TDSD_PROJECT_WALLET_ADDRESS=<project TON wallet owner>
```

## 2. Build And Test

```bash
npm run build
npm test
```

Do not continue if compile or sandbox tests fail.

## 3. Deploy Jetton Master

```bash
npm run deploy:testnet
```

Record:

- `TDSD_JETTON_MASTER_ADDRESS`
- `TDSD_PROJECT_JETTON_WALLET`
- owner/admin address
- wallet code hash
- content cell hash

## 4. Verify On Testnet

Use a TON testnet explorer and the getter script:

```env
TDSD_JETTON_MASTER_ADDRESS=<master>
TDSD_WALLET_OWNER=<project owner wallet>
```

```bash
npm run get:data
```

Verify:

- `get_jetton_data` returns the expected admin;
- metadata points to TDSD content;
- wallet code hash matches the built artifact;
- `get_wallet_address(project owner)` matches the project Jetton wallet used by backend.

## 5. Mint Test Supply

Mint only from the admin wallet:

```env
TDSD_JETTON_MASTER_ADDRESS=<master>
TDSD_MINT_RECIPIENT=<project or test recipient owner wallet>
TDSD_MINT_AMOUNT_UNITS=1000000000000
```

```bash
npm run mint:testnet
```

Then re-run:

```bash
npm run get:data
```

## 6. Connect Backend

Update backend env:

```env
SEED_TDSD_ASSET=true
TDSD_ASSET_SYMBOL=TDSD
TDSD_ASSET_NAME=Tuda Suda Token
TDSD_DECIMALS=9
TDSD_NETWORK=ton_testnet
TDSD_JETTON_MASTER_ADDRESS=<master>
TDSD_PROJECT_JETTON_WALLET=<project jetton wallet>
TDSD_DEPOSITS_ENABLED=true
```

Apply database state:

```bash
cd ../backend
alembic upgrade head
python production_seed.py
```

Check:

```text
GET /assets
GET /ready
```

TDSD must be active, have `provider_key=jetton`, and expose the deployed
contract address.

## 7. Test Backend Deposit Flow

1. Log in through Telegram Mini App.
2. Connect TON wallet.
3. Create a TDSD deposit in the app.
4. Send TDSD with the exact memo/comment generated by backend.
5. Click “check status”.
6. Confirm:

- deposit status is `confirmed`;
- `AssetBalance.balance_units` increased for TDSD;
- `AssetLedgerEntry.entry_type=deposit`;
- balance appears in frontend.

## 8. Test Internal Gifts

1. Ensure at least two users exist.
2. Give one user a TDSD balance through a confirmed deposit.
3. Send an internal TDSD gift.
4. Confirm:

- sender balance decreases;
- receiver balance increases;
- sender ledger has `gift_sent`;
- receiver ledger has `gift_received`;
- `AssetGift` is `completed`;
- karma and leaderboard update.

## 9. Mainnet Gate

Mainnet is blocked until:

- testnet E2E is completed;
- failed and duplicate deposit paths are tested;
- admin controls are reviewed;
- monitoring and backups are enabled;
- external smart-contract audit is complete.
