# TDSD_PURCHASE_WALLET_BLOCK_FIX_REPORT

## Что исправлено

Обновлен `frontend/src/App.jsx`.

Кнопка `Купить TDSD` больше не блокируется из-за отсутствия сохраненного кошелька или несовпадения сохраненного адреса с подключенным TonConnect-адресом.

Теперь кнопка disabled только если:

- идет создание покупки;
- TonConnect-кошелек не подключен;
- TDSD asset не выбран.

## Автосохранение кошелька

Перед созданием `asset deposit` frontend проверяет текущий подключенный `connectedTonAddress`.

Если адрес:

- еще не сохранен в профиле;
- или отличается от сохраненного адреса;

frontend сначала вызывает существующий API сохранения кошелька, обновляет `dashboard.user` и `savedWallet`, а затем продолжает создание покупки.

Если сохранение не удалось, пользователь видит:

`Не удалось сохранить подключенный кошелек`

## Почему payout не уйдет на старый savedWallet

`api.createAssetDeposit()` вызывается только после успешного `api.connectWallet(connectedTonAddress)`, когда backend уже сохранил актуальный адрес пользователя.

Backend hot wallet, payout, fixed-price расчет и Toncenter logic не менялись.

## Проверочные сценарии

1. Подключенный, но не сохраненный кошелек:
   - кнопка `Купить TDSD` активна;
   - перед покупкой адрес сохраняется автоматически;
   - затем создается покупка.

2. Подключенный новый кошелек вместо старого:
   - кнопка активна;
   - старый saved wallet не блокирует покупку;
   - перед покупкой сохраняется новый connected address;
   - deposit создается уже с актуальным адресом пользователя.

3. Уже сохраненный совпадающий кошелек:
   - кнопка активна;
   - повторное сохранение не выполняется;
   - deposit создается сразу.

4. Полностью неподключенный кошелек:
   - кнопка остается disabled;
   - покупку создать нельзя до подключения кошелька.
