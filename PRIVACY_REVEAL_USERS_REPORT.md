## Где скрыты никнеймы

Никнеймы скрыты на backend-уровне, а не через CSS.

Изменены публичные сериализаторы:

- `/transactions/public`
- `/leaderboard`
- `/asset-gifts`
- `/asset-gifts/leaderboard`

По умолчанию API возвращает:

- `Скрытый пользователь`
- `Получатель скрыт`

Настоящие `username` / `first_name` не отправляются во frontend, пока конкретная запись не раскрыта для текущего пользователя.

В личном профиле пользователь по-прежнему видит свой никнейм.

## Как работает раскрытие пользователя

Добавлен endpoint:

```http
POST /users/reveal
```

Body:

```json
{
  "context_type": "asset_gift",
  "context_id": "asset-123",
  "target_role": "sender"
}
```

Backend сам определяет, какой пользователь скрыт за конкретным контекстом:

- `virtual_gift`
- `asset_gift`
- `referral_reward`
- `leaderboard`
- `asset_gift_leaderboard`

После успешной оплаты раскрытие действует только для оплатившего пользователя.

## Как списываются 10 TDSD

Реализован вариант `internal ledger`.

Причина: в проекте уже есть внутренний TDSD ledger (`asset_balances` и `asset_ledger_entries`), а требование запрещает списывать TDSD без подтверждения. Нажатие на кнопку раскрытия является явным подтверждением.

Цена:

```text
10 TDSD
```

Backend:

- проверяет баланс TDSD;
- если баланса не хватает, возвращает `Недостаточно TDSD`;
- списывает 10 TDSD с баланса viewer;
- создает ledger entry `user_reveal`;
- начисляет 10 TDSD treasury-пользователю как `treasury_income`;
- сохраняет факт раскрытия.

On-chain transfer для раскрытия не используется. HOT_WALLET_ADDRESS не нужен для этой внутренней операции и не затрагивался.

## Где хранится факт раскрытия

Добавлена таблица:

```text
user_reveals
```

Поля:

- `id`
- `viewer_user_id`
- `revealed_user_id`
- `context_type`
- `context_id`
- `target_role`
- `price_units`
- `created_at`

Есть уникальность:

```text
viewer_user_id + context_type + context_id + target_role
```

Это защищает от повторного списания за одно и то же раскрытие.

## Какие API изменены

- `GET /transactions/public`
  - теперь персонализирован под текущего пользователя;
  - возвращает скрытые имена и `sender_reveal` / `receiver_reveal`.

- `POST /users/reveal`
  - новый endpoint оплаты раскрытия.

- `GET /leaderboard`
  - теперь скрывает имена пользователей.

- `GET /asset-gifts`
  - скрывает контрагента по TDSD-подарку.

- `GET /asset-gifts/leaderboard`
  - скрывает имена участников.

## UX изменения

- Во вкладке `Все` имена скрыты.
- В публичных операциях показываются кнопки `Раскрыть пользователя — 10 TDSD`.
- В профиле убран отдельный пункт `Telegram ID`.
- Telegram ID перенесен в верхний блок профиля как `ID: <telegram_id>`.
- Пункт `Репутация` и popup репутации удалены из UI.
- Описание `Карма` оставлено нейтральным: активность, переводы TDSD, участие в проекте и приглашения.
- Удалены пользовательские тексты про доверие, корректное поведение и уровень доверия.

## Как проверить после деплоя

1. Открыть вкладку `Все`.
2. Убедиться, что вместо имен видны `Скрытый пользователь` и `Получатель скрыт`.
3. Нажать `Раскрыть пользователя — 10 TDSD`.
4. Если TDSD меньше 10, должен появиться текст `Недостаточно TDSD`.
5. Если TDSD достаточно:
   - баланс уменьшается на 10 TDSD;
   - конкретная запись раскрывается только для текущего пользователя;
   - другие пользователи продолжают видеть скрытое имя.
6. Открыть профиль:
   - отдельного пункта `Telegram ID` нет;
   - в верхнем блоке видно `ID: <telegram_id>`;
   - пункта `Репутация` нет;
   - описание `Карма` не содержит удаленные фразы.
7. Проверить сборку frontend и старт backend.
